# The grind

A tracker for a 12-month study plan, 3 November 2026 to 31 October 2027.
One page, no backend, no build step.

Live at **https://aryan-winningson.github.io/grind-tracker/**

## Where progress is kept

Every change is written to `localStorage` straight away, so the page works with
no connection and never waits on the network.

Sync is optional and off until you turn it on. When it is on, the same progress
is mirrored to a **secret gist** on your own GitHub account, in two files:

| file | what it is |
| --- | --- |
| `grind-progress.md` | the day-by-day log, readable on its own |
| `grind-data.json` | the same thing in the form the page reads back |

The gist is the source of truth. Clearing a browser loses nothing but the
token; open the page again and everything comes back.

## Setting up a device

The first device needs a token once:

1. Create a GitHub token with **only** the `gist` scope.
2. Open the Data tab, paste it, press **Turn on sync**.

Every device after that is set up from the first one: Data tab → **Show QR
code** → scan it with the new device's camera. The token rides in the part of
the URL after the `#`, which browsers never send to a server, and the page
removes it from the address bar as soon as it has been stored.

> The token is never committed to this repository and never leaves your
> devices. Don't put one in the source — GitHub's secret scanning revokes
> tokens found in public repos, so it would stop working within minutes anyway.

## How two devices are reconciled

Each device reads the gist before it writes, and merges rather than overwrites,
so working offline on a laptop and a phone at the same time keeps both sides:

- **Checks** — the activity log is append-only, so both copies are unioned and
  the newest event for each item decides. An uncheck on one device survives.
- **Metrics** — settled the same way, from their own timestamped history.
- **Notes and hours** — free text, so the most recent edit wins, using
  per-field edit timestamps.
- **Theme** — never travels; it stays a per-device choice.

Importing a file or erasing everything are deliberate replacements, so those
overwrite the gist instead of merging into it.

## Offline and on a phone

`sw.js` caches the page so it opens without a connection. The page itself is
fetched network-first, so a new version appears as soon as it is published.

Add it to the home screen on a phone. On iOS this matters: Safari clears a
site's storage after seven days without a visit, which would sign you out of
sync, and pages on the home screen are exempt.

## Files

```
index.html              the whole app — plan, UI, sync, QR encoder
sw.js                   offline cache
manifest.webmanifest    home-screen install
icon-*.png              generated by tools/mkicon.py
```

## Running it locally

```sh
python3 -m http.server 8000
```

Then open <http://127.0.0.1:8000/>. Opening `index.html` as a file works too,
but the service worker and the manifest need a real origin.
